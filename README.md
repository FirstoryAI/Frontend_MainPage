# FIRSTORY Frontend

FIRSTORY의 랜딩 및 인증 진입 화면을 구현한 React 프론트엔드입니다. Figma의 `start` 노드(`613:1044`)를 기준으로 구성했습니다.

## 시작하기

```bash
npm install
npm run dev
```

환경 변수는 `.env.example`을 복사해 `.env`에서 관리합니다.

```dotenv
API_PROXY_TARGET=https://backendmainpage-production.up.railway.app
```

## 명령어

- `npm run dev`: Vite 개발 서버 실행
- `npm run lint`: ESLint 검사
- `npm run build`: 프로덕션 빌드
- `npm run preview`: 빌드 결과 미리보기
- `npm run mock-api`: 가짜 API 서버만 실행 (포트 8787)
- `npm run dev:mock`: 가짜 API 서버와 개발 서버를 함께 실행

## 서버 API 점검 (`npm run check-api`)

실제 서버가 프론트가 기대하는 대로 동작하는지 터미널에서 점검합니다. 본인 테스트 계정으로 로그인해 확인하고, 결과를 `[OK]`/`[실패]`로 보여 줍니다. 비밀번호는 저장하지 않습니다.

```powershell
$env:FIRSTORY_EMAIL = '테스트 계정 이메일'
$env:FIRSTORY_PASSWORD = '테스트 계정 비밀번호'
npm run check-api                 # 읽기 점검: 내 정보·홈·서재·아이 프로필·표지 그림
npm run check-api -- --errors     # + 예외 상황: 로그인 없음·잘못된 값·없는 동화·상태 오류·위기 신호(분위기 선택·차단)
npm run check-api -- --flow       # + 동화 한 편을 끝까지 (AI 인터뷰 질문, 글, 그림 8장, 서재 표지) — 몇 분 걸림
```

- 주소는 `API_BASE` 환경 변수, 없으면 `.env`의 `API_PROXY_TARGET`을 씁니다. 가짜 서버(`npm run mock-api`)에도 같은 방법으로 쓸 수 있습니다.
- `--errors`, `--flow`는 점검용 임시 동화를 만들고 끝나면 지웁니다. (`--keep`을 붙이면 `--flow` 동화를 남깁니다.) 동화 확정이나 탈퇴는 하지 않습니다.

## 서버 없이 확인하기 (가짜 API 서버)

`scripts/mock-api.mjs`는 API 명세(`/v3/api-docs`)를 따라 하는 개발용 서버입니다. 실제 서버에 계정을 만들지 않고도 가입부터 동화 만들기·미리보기·확정·함께 읽기까지 전체 흐름을 눌러 볼 수 있습니다.

- `npm run dev:mock`으로 실행하면 개발 서버가 가짜 서버(`http://localhost:8787`)를 바라봅니다. (`.env`의 `API_PROXY_TARGET`보다 우선)
- 휴대폰 인증번호는 항상 `000000`이고, 이메일·비밀번호는 아무 값이나 됩니다.
- 처음에는 동화가 하나도 없고, 실제처럼 직접 만들어야 생깁니다. 상태별 예시 동화(제작 중·확인을 기다려요·아직 읽지 않았어요·함께 읽었어요·만들지 못했어요)가 필요하면 `npm run dev:mock -- --seed`처럼 `--seed`를 붙여 실행하세요.
- 동화 만들기는 약 12초(단계당 3초)면 끝납니다. `MOCK_STAGE_MS`로 바꿀 수 있습니다.
- 글에 `이별`이 들어가면 서버가 민감 주제로 판단(화면은 띄우지 않고 동화 만들기 때 분위기를 '아직 잘 모르겠어요'로 정해 둠), `위기`가 들어가면 다시 쓰기 안내, `자해`가 들어가면 입력 단계의 안내 문구(차단 화면은 동화 만들기를 눌렀을 때만 나옴), 상황 설명에 `실패테스트`가 들어가면 동화 만들기 실패를 볼 수 있습니다. 상황 설명에 `바로정리`가 들어가면 인터뷰 질문 없이 바로 마무리 화면으로 넘어갑니다. 상황 설명에 `검토차단`이 들어가면 동화 만들기를 누르는 순간 안내 화면(409 `STORY_BLOCKED`)이, `생성차단`이 들어가면 만드는 중에 안내 화면(`BLOCKED`)이 나옵니다.
- 인터뷰를 마친 뒤(생성 전 확인)에도 상황·아이·전하고 싶은 말을 고칠 수 있고, `나누고 싶은 것`은 `PUT /summary`로 저장합니다. 동화는 10쪽이고, 대화 가이드는 확정 전에도 볼 수 있습니다. (백엔드 10/27 배포 기준)
- 데이터는 메모리에만 있어 서버를 끄면 사라집니다.
- 5173 포트를 이미 `npm run dev`(실제 서버)가 쓰고 있으면 `npm run dev:mock -- --port 5190`처럼 다른 포트로 실행하세요. 브라우저에서 `localhost:5173`은 실제 서버용 개발 서버로 연결될 수 있으니, 가짜 서버를 쓸 때는 반드시 주소의 포트를 확인하세요.

## 구조

```text
src/
├── app/                  # 앱 셸과 라우터
├── assets/               # Figma 이미지, 아이콘, 로컬 폰트
├── components/layout/    # 페이지 공통 레이아웃
├── features/auth/        # 인증 도메인 UI
├── pages/                # 라우트 단위 페이지
├── services/             # 공통 API 클라이언트
└── styles/               # 리셋, 전역 스타일, 디자인 토큰
```

현재 인증 흐름은 `/` → `/auth/email/signup` → `/auth/consent` → `/home`으로 연결됩니다. 필수 동의 3개를 체크하고 `시작하기`를 누르면 홈(`home` 노드 `628:1061`)이 열리고 첫 방문 온보딩 모달이 함께 뜹니다(`location.state.onboarding`). 이 모달은 `첫 동화 만들기` 버튼으로만 닫히고, X 버튼·배경 클릭·Esc는 아무 동작도 하지 않습니다. 모달의 `첫 동화 만들기`와 홈의 `동화 만들기` 버튼은 `/story/new`로 이동합니다.

`/story/new`는 한 페이지 안에서 단계가 바뀌는 흐름입니다(`features/story`, 진행 바 값은 `constants.js`의 `progressByStep`).

| 단계 | Figma 노드 |
| --- | --- |
| 상황 선택 | `628:957` (선택 상태 `628:2448`) |
| 내용 입력 | `628:983` |
| 아이 정보 | `628:1014` |
| 이야기 | `628:1206` (`아직 잘 모르겠어요` 선택 상태 `628:1428`) |
| AI 채팅 | `628:1370` |
| 마무리(요약) | `628:1230` |
| 아이 정보 수정 모달 | `628:2279` |
| 동화 만드는 중 (이야기 짜기 → 글 쓰기 → 그림 그리기) | `628:1343` → `628:1316` → `628:1289` |

흐름: 이야기 단계에서 `아직 잘 모르겠어요`를 고르고 `다음`을 누르면 AI 채팅으로, 직접 이야기를 적으면 바로 마무리로 이어집니다. 채팅은 준비된 질문에 답하면(또는 `여기까지 답하고 넘어가기`) 마무리로 넘어가고, 마무리의 `동화 만들기`를 누르면 동화 만드는 중 화면이 열립니다. 뒤로가기 화살표는 직전에 있던 단계로 돌아갑니다.

- **카테고리별 문구**: `어떤 일인가요?`에서 고른 카테고리에 따라 설명·이야기 화면의 예시 문장과 채팅의 보호자 첫 답·AI 질문·빠른 답변 3개, 마무리의 `나누고 싶은 것`이 바뀝니다. 모든 문구는 `features/story/categoryContent.js` 한 곳에 있고, `친구 관계`만 Figma 문구이며 나머지는 임시 문구입니다.
- **마무리 화면**: `아이`·`상황`·`이번 이야기에서 나누고 싶은 것`의 `수정하기`는 모두 같은 틀(`EditModal`: 흐린 배경, 흰 카드, X, 저장하기)의 모달이 열립니다. 아이는 `ChildEditModal`, 나머지 둘은 글을 고치는 `TextEditModal`이고, 저장해야 반영되며 X·Esc로 닫으면 고친 내용은 버려지고 배경을 눌러도 닫히지 않습니다. 고친 `상황`은 설명 단계의 입력값도 함께 바뀝니다. 마무리 디자인(`628:1230`)에는 캐릭터 레이어가 없지만 같은 자리에 캐릭터가 들어갈 자리(`628:2279`의 회색 원)가 있어, 이야기 화면과 같은 캐릭터를 같은 위치 규칙으로 말풍선 왼쪽에 넣었습니다.
- **단계 이동**: 단계가 바뀔 때마다 화면 맨 위로 스크롤합니다.
- **동화 만드는 중**: `generation/StoryGenerationProvider.jsx`가 서버의 진행 상태(`GET /api/stories/{id}/generation`)를 3초마다 읽어 오고, 화면을 나가도 이어서 따라갑니다. 다 되면(`REVIEWING`) 제작 완료 화면과 홈 알림이 생기고, 실패하면 실패 화면(`GenerationFailedStep`: 같은 내용으로 다시 만들기·입력내용 고치기)과 알림이 생깁니다. 알림 번호는 내 정보(`phoneMasked`)에서 가져오고 `번호 바꾸기`는 연결되어 있지 않습니다.
- **진행 바**: Figma 값이 있는 단계(160·291·460·862px)를 따르고, 디자인에 값이 없던 이야기·채팅 단계는 이전보다 더 차도록 600px·740px로 잡았습니다. 동화 만드는 중 화면은 진행 바가 없습니다.
- **서버 연동**: 동화 만들기의 입력은 단계마다 서버에 저장됩니다(`POST /api/stories` → 상황·아이·전하고 싶은 말 → AI 인터뷰 → 동화 만들기 시작). 화면 문구와 API 값의 변환은 `features/story/storyMappers.js`에 있습니다. 서버(API 명세)는 인터뷰를 시작한 뒤에는 상황·아이 정보·전하고 싶은 말 수정을 받지 않아, 이전 단계로 돌아가 고치거나 마무리 화면에서 `수정하기`를 하면 `동화 만들기`를 누를 때 새 동화로 다시 만들어 보냅니다. 인터뷰를 시작하기 전의 입력은 그대로 서버에 보내고, 수정할 때는 앞서 인터뷰에서 한 답을 그대로 다시 보냅니다. 위기 신호 검사 결과는 다시 쓰기(안내 문구), 차단(`BlockedStep`, Figma 628:2058), 분위기 선택(`ToneDialog`)으로 보여 줍니다. 차단 화면의 상담 기관 이름·연락처는 디자인에 자리만 있어 `features/story/helpOrganizations.js`에 임시로 두었습니다. 다시 쓰기·분위기 선택은 디자인이 없어 기존 팝업 모양을 따랐습니다.
- **임시 저장**: 서버에 저장된 만들던 동화(`DRAFT`·`INTERVIEWING`·`CONFIRMING`)를 `동화 만들기` 팝업의 `임시 저장한 동화`에서 이어 만들 수 있습니다.
- **서재·미리보기·읽기**: 서재 카드는 상태에 따라 미리보기(`/story/:id/preview`), 동화 상세(`/library/:id`), 이어 만들기·진행 보기로 열립니다. 미리보기에서 다시 만들기(`regenerate`)·확정(`approve`)(오른쪽 `동화 설명`은 동화 줄거리, `부모를 위한 가이드`는 서버가 확정 전에도 대화 가이드를 주면 쪽마다 보여 줍니다. 지금 명세는 확정(`COMPLETED`) 후에만 줍니다), 동화 상세에서 삭제·대화 가이드·함께 읽기(읽기 세션, 쪽 넘김, 대화 버튼, 다 읽음)가 서버와 연결되어 있습니다.
- **마이페이지**: 아이 정보(`/api/children`), 카카오톡 알림 토글(`smsNotify` 동의), 탈퇴(비밀번호 확인)가 서버와 연결되어 있습니다. 비밀번호·휴대폰 번호 변경, 아이 호칭 변경, 버전 되돌리기 API는 `services/`에 호출 함수만 있고 화면은 아직 없습니다.
